# AGENTS.md

## Conventions for this repo

### Reporting PR results

When explaining the results of a PR (or summarizing completed work), always structure the report as:

- **Problem** — the user-facing symptom.
- **Cause** — what in the code produced it.
- **Fix** — what changed and how.
- **What this means for the user** — the concrete impact, described from the user's perspective (e.g. what they can now do, or what no longer goes wrong).

Use a concrete example per item, tied to the actual change, rather than abstract descriptions.
